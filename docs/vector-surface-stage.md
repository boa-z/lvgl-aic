# Native vector target representation and clipping

Historical surface-stage record. The later [translucent blend correction](vector-blend-stage.md)
resolves the multiply/screen gap described below and expands the board probes.

The pinned software vector backend previously wrote premultiplied ThorVG pixels
directly into straight-alpha ARGB canvas/layer storage. Existing translucent
backdrops and subsequent image composition could therefore use different alpha
representations. Its RGB565/RGB888 temporary image was also blended as straight
ARGB, and a subtask viewport could replace the outer task clip or a previously
queued subtask's viewport. The new host regression reproduced writes outside
an offset task clip before correction (`output/vector-surface-before.log`).

This stage corrects the native LVGL/ThorVG software path used by canvas and SVG.
It adds no GE vector acceleration and is not an absent SDK GE primitive.
The upstream LVGL and SDK source trees stay unchanged. A SHA-guarded application
build generator replaces only `lv_draw_sw_vector.c`; host and target use the
same generated unit. Final-link checks require its live symbol ownership and
exact generated bytes, and the image manifest records the generated source.

## Drawing and ownership

The renderer intersects task clip with the target view, allocates a bounded
premultiplied ARGB surface, and seeds it from the actual backdrop. It renders
with coordinates relative to that clipped area, then converts changed pixels
back to the original representation. Supported targets are RGB565, RGB888,
XRGB8888, straight ARGB8888, explicit/flagged premultiplied ARGB8888 and RGB565A8
with separate color and alpha planes. Source-over operates on both color and
alpha; opaque multiply/screen retain their destination-dependent results.

Unchanged pixels retain exact original bytes, including hidden RGB at alpha zero,
unused X bytes, row padding and low-alpha colors whose premultiply/unpremultiply
round trip would lose precision. Target format/flags are not changed. Modified
straight-alpha pixels pass through eight-bit premultiplication, so very small
alpha values can amplify quantization on unpremultiplication. This is not a
floating-point renderer or arbitrary-edge pixel-equivalence guarantee.

ThorVG's viewport is canvas-wide. Each vector subtask is drawn and synchronized
before releasing its paints and moving to the next scissor, preserving paint
order and the original backdrop. This adds synchronization overhead; board
throughput remains unmeasured. No ThorVG workers or asynchronous rendering are
enabled by this component.

`AIC_LVGL_VECTOR_SURFACE_BYTES` defaults to 4 MiB (configurable 4 KiB..16 MiB),
additional to LVGL layer, GE and parser storage. Only clipped target pixels need
scratch. Malformed/unsupported views, oversized scratch, allocation failure and
checked canvas creation/target/draw/sync/clear failures preserve the target and
release the consumed native vector task list. The task is skipped with a warning;
there is no second renderer fallback. Native internal shape/gradient/parser
allocation assertions and every C++ failure path are not covered by this gate.

## Verification

- Combined host **91/91 PASS** (43.59 s); disabled baseline **81/81 PASS** (21.81 s).
- 182 analytic scenes cover seven target encodings, transparent/partial/opaque
  backdrops, three source opacities, independent split scissors and opaque
  multiply/screen. All 262,808 channel checks pass with tolerance four (nine for
  RGB565 quantization). Nonzero origins, outer clipping, row padding and guards
  are checked independently of interior samples.
- Seven allocation failures and 35 canvas failures preserve the complete target
  byte-for-byte and release scratch. Eight invalid/empty/over-budget views reject
  before allocation or pixel access, including a short RGB565A8 alpha plane.
- The seven offscreen board probes are also compiled and run through actual
  native canvas/task dispatch on host: ten lifetimes, 70 scenes, balanced layer
  lists and layer memory. They log `PASS vector surface`; physical execution is
  **NOT_RUN**. Direct surface tests use the real ThorVG rasterizer, not a mock.
- Refreshed vector/SVG contracts **7/7 PASS** (0.34 s); minimal SVG without
  FreeType also **7/7 PASS** (2.60 s).
- Logs: `output/vector-surface-{build,tests,baseline-build,baseline-tests,final-build,final-tests,minimal-build,minimal-tests}.log`.

At this stage, a separate native ThorVG arithmetic gap was recorded: partial-opacity
multiply does not retain the expected destination contribution. For an opaque
backdrop with blue 48 and source blue 32 at opacity 128, the backend returns 3
instead of approximately 27. The explicit command
`lvgl_aic_vector_surface_contract.exe translucent-blend` reproduced
that failure at the original implementation pin; `output/vector-translucent-blend-gap.log` records it. The original green
contracts certified source-over and opaque special blends only. The later
[blend stage](vector-blend-stage.md) corrects and tests the translucent case. SVG group opacity,
other blend formulas, gradient/document semantics and hardware timing remain
separate work. See [validation](validation.md) for clean firmware evidence.

Full combined D13x boot/app, final-link/static, image and clean manifest gates
**PASS**. All 31 recorded artifact hashes, three source pins and SDK gitlink were
independently verified. The corrected renderer and seven-probe runner are live
in ELF; probe/failure markers are in allocated `.rodata`. Nine image CRCs and 41
fixture/provenance hashes pass. This firmware includes the new staging budget
and probes, but physical execution remains NOT_RUN. Exact pins/hashes are in
[validation](validation.md); log `output/vector-surface-firmware.log`.
