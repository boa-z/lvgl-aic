# Software rotation precision

The GE center guard exposed a native LVGL fallback defect: for a 32x32 source,
pivot (16384,16384), origin (100,230) and 0.1-degree rotation, the Q10 forward
bounds and inverse sampling disagreed enough to produce no visible pixels.
The independent geometry regression first reproduced an approximately 29-pixel
Y error. Merely declining the hardware command could not preserve the image.

The component now stages source-fingerprinted copies of `lv_area.c` and
`lv_draw_sw_transform.c` in the build directory. The pinned upstream checkout
and SDK sources remain untouched. Both copies use the same Q15 coefficients:
degree interpolation retains its tenths numerator, a reciprocal-square-root
step corrects chord contraction, and symmetric rounding occurs once. Forward
and inverse angles normalize modulo a full turn. Cardinal coefficients remain
exact. Forward products and software column-step products use 64-bit arithmetic;
the inverse anchors and Q16 increments retain their clip-independent definition.

SCons and host CMake substitute both units together. Source drift fails staging
until reviewed. The target integration check verifies generated bytes and live
symbol ownership; the evidence manifest includes both generated sources.

## Verification and limits

- 420 ARGB8888 drawing scenes cover normal and remote positive/negative pivots
  through magnitude 32768, negative and wrapped angles, 0.5x/1.5x per-axis and
  2x scaling, both antialias settings, a translated layer and clipped rendering.
- 161,734 interior pixels match an independent double-precision inverse oracle.
  Exterior pixels remain clear. Pixel-boundary uncertainty is excluded explicitly;
  this is not an assertion of exact ideal bilinear edge coverage.
- All scenes are byte-identical when drawn in one operation or 17x13-pixel clips.
- 108,000 forward probes sweep every 0.1-degree angle and both scale orders.
  Maximum measured coordinate error is 3.707 pixels at the tested large pivots
  and scales, within the declared four-pixel bound. This remains fixed-point
  table geometry, not arbitrary-pivot subpixel accuracy.
- The GE executor test now checks actual IMAGE and LAYER software handoff at
  the ideal center of both the original 0.1-degree and 45-degree reproducers,
  with no preceding cache preparation or hardware command.

Combined host **80/80 PASS** and vector/SVG/Lottie-disabled baseline **75/75
PASS**. Combined D13x boot/app compilation, generated-source/live-symbol checks,
image and clean-source manifest gates also pass; exact pins and hashes are in
[validation](validation.md).
Hardware execution remains **NOT_RUN**; target timing and numeric/visual rotation
acceptance are deferred. This change does not establish an unbounded int32
coordinate/scale domain, change GE Q2.12 arithmetic, or implement hardware
arbitrary-angle scaling. The latter still requires a bounded multi-pass design.
