# SVG groups, references and stroke ownership

The native LVGL 9.6 SVG adapter now corrects four reproduced document failures:

- An unresolved external `<image>` applied its transform and returned without
  restoring it, moving later siblings. The early exit now restores the context.
- `<use x/y>` passed its translation down to a leaf, so a referenced group's
  scale/rotation changed the placement. Translation now joins the use context
  before the referenced subtree's transforms; nested uses preserve that order.
- A use's inherited solid paint could override the referenced element's explicit
  color. The referenced element's explicit attributes now override inherited use
  context; a definition without an explicit fill still inherits the use fill.
- Builder stack nodes, saved group contexts and saved text-span contexts owned
  copied stroke-dash arrays but did not release all of them. Each matching pop /
  render exit now deinitializes its owned copy.

These are native SVG rendering/lifetime corrections, not omitted SDK GE features
or GE vector acceleration. They remain in the application component's SHA-guarded
build generator. SDK and pinned LVGL source trees are unchanged. Host and target
both replace the same SVG renderer translation unit; target checks verify its
live symbol owner and exact generated bytes, and provenance saves the generated
renderer along with the image/decoder corrections.

## Reference boundaries

Missing hrefs and unresolved IDs draw nothing for that use. Active reference
cycles and chains exceeding 32 active use nodes are skipped for the affected
branch, preserving subsequent siblings and later independent renders. Rendering
and reference-bound queries have separate balanced stacks. Native SVG rendering
and these stacks are serialized on the LVGL owner, as are parser/cache/font
operations. The limit is on use references, not syntactic group nesting, total
reference expansion, document/parser heap or general SVG validity.

Group/element opacity is now implemented in the subsequent [opacity stage](svg-opacity-stage.md). General inherited paint/gradient semantics, external
asset/font providers, transformed group bounds, and full text layout are not
claimed complete. The outline text test below proves rendering and ownership,
not typography equivalence. Existing native image effects and transform limits
remain as described in [composition](svg-composition-stage.md).

## Verification

The original missing-image placement, scaled-use placement, explicit fill
precedence and grouped-dash lifetime tests failed before correction. The current
contract runs ten analytic fixtures over 200 direct/decoded-image render scenes:
missing images, scaled/rotated/nested references, explicit/inherited solid fill,
missing href/ID and direct/mutual cycles. Three interior/background samples per
scene use a two-level RGB tolerance for native vector rounding. Reference bounds
are also queried independently before drawing each document.

Reference chains of 31/32/33/41 active uses check the exact 32-use boundary; a
valid subsequent render checks stack cleanup. One hundred grouped dashed-path
parse/render/delete lifetimes keep LVGL tracked heap bytes constant. Twenty
FreeType outline `<tspan>` lifetimes do likewise while producing nonempty glyph
pixels. Every tracked LVGL allocation is released at test teardown. These
allocation counts do not measure ThorVG's C++ heap or prove all internal OOM paths.
