# Video window composition and image extents

The SDK video-window API describes an alpha-zero `.fake` image so a lower video
plane remains visible. The application LVGL 9.6 port now verifies this path
through the normal image widget and draw scheduler. Metadata reports ARGB8888
for blended fake colors and XRGB8888 for opaque replacement colors; GE's fake
executor still owns the encoded replacement/source-over arithmetic.

The offscreen contract paints a real ARGB8888 screen, draws the video window,
repaints it repeatedly, moves/resizes/hides/restores it and checks every pixel
and guard row. It runs with GE unavailable (software), a heap destination that
cannot use GE (software fallback), and an address-valid GE model (descriptor
fill execution). It also checks the image cover result stays non-cover when
alpha is present, and verifies 0/90/180/270-degree inclusive bounds for both
16x8 and 8x16 windows. No display, DE, panel or camera binding is assumed.

A pinned LVGL source correction adds one to transformed image right/bottom
excess calculations. LVGL areas use inclusive endpoints; the previous widget
extension calculation could clip the last row or column of a rotated image.
The correction is generated by `stage_sw_rotation.py`, guarded by the exact
LVGL source hash, and used by host CMake and the SDK SCons application build.

Host full profile: **93/93 PASS**, including 171 real widget/pseudo-image
refreshes and the video-window render contract. The focused contract exercises
GE unavailable, heap fallback and GE descriptor fill paths. The target manual
runner adds twelve offscreen probes and is required in the GE2D final link.
Physical DE alpha/scanout, camera/player timing and panel pixels remain
**NOT_RUN**.
